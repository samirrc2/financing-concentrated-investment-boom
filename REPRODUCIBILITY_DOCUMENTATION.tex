\section{Purpose and scope}
This document describes the supporting data-and-code archive that accompanies the manuscript. The
archive is a self-contained, \textbf{offline, deterministic} reproduction: from a single command it
regenerates every reported number, table and figure from frozen inputs, with \textbf{no network
access, no API keys and no paid calls}. The permanent citable version is the Zenodo deposit at
[[DOI PENDING]] (code MIT-licensed).

A strict wall separates two phases. An \emph{offline analysis} reproduces every claim from the
frozen inputs (documented here). A \emph{collection} phase originally queried public SEC and BLS
endpoints and is retained for transparency only (Section~9). Because the SEC's \emph{frames}
interface returns the most recently filed value for each fact, re-collecting today would pick up
subsequent filer restatements and would not reproduce the frozen inputs; collection is therefore
deliberately not part of the reproducible core.

\section{Quick start}
\begin{quote}\texttt{pip install -r requirements.txt}\\ \texttt{./verify.sh}\end{quote}
\textbf{Expected result:} the archive verifies against its SHA-256 manifest, the analysis re-runs
from the frozen inputs, the regenerated \code{claims.json} and figure are byte-identical to the
committed ones, every number in the manuscript reconciles to \code{claims.json}, the manuscript is
within the journal's length limit, and the script exits 0. Total runtime is under ten seconds on a
standard laptop. No network access is required at any point.

\subsection{Provenance and integrity}
\code{data/SHA256SUMS.txt} fixes every frozen source file; \code{MANIFEST.sha256} fixes every file in
the archive, including the code and the manuscript. The collection scripts write their outputs
read-only and refuse to overwrite an existing frozen file, so a silent change to an input is
detectable before the analysis runs. \code{verify.sh} checks both manifests before it runs anything.

\section{Tracing a reported figure to its source}
A reviewer who wants to check a number rather than re-run the pipeline can go from any figure in the
paper to the SEC endpoint it came from in one command. \code{code/trace.py} prints every tag the
series unions, the frozen value under each, the exact URL, which tag wins the union, and the
deflated figure the paper uses.

\begin{quote}\texttt{python3 code/trace.py -{}-firm Alphabet -{}-series capex -{}-year 2025}\end{quote}
\begin{quote}\footnotesize\ttfamily
Alphabet Inc.\ (CIK 1652044)\ \ capital expenditure\ \ fiscal year 2025\\[2pt]
PaymentsToAcquirePropertyPlantAndEquipment\ \ \ \$91.447bn\\
\hspace*{1em}\seqsplit{https://data.sec.gov/api/xbrl/frames/us-gaap/PaymentsToAcquirePropertyPlantAndEquipment/USD/CY2025.json}\\
PaymentsToAcquireProductiveAssets\ \ \ not filed\\[2pt]
union takes the maximum across tags -> \$91.447bn (nominal)\\
deflated to 2025 dollars (WPUFD41312, 224.732/224.732): \$91.447bn
\end{quote}

Adding \code{--live} re-fetches from the SEC and reports whether the live value still matches the
frozen copy, printing the accession number of the filing that supplies it. \code{--list} shows the
eight series available and the five focal firms. A live difference is a filer restatement since the
freeze, not an error; it is precisely why the archive is built from the frozen copies and why the
paper reports them.

\textbf{Worked example: the 117\% at the top five (Table~1).} The five largest incremental
investors are Alphabet, Amazon, Oracle, Meta and Microsoft. For each, the paper cumulates the
2022--2025 increment of capital expenditure and of operating cash flow against a 2021 baseline, in
2025 dollars, and divides the second sum by the first. Every component is one \code{trace.py} call:
\begin{quote}\texttt{for f in Alphabet Amazon Oracle Meta Microsoft; do \textbackslash}\\
\texttt{\ \ python3 code/trace.py -{}-firm \$f -{}-series capex -{}-year 2025 -{}-live; done}\end{quote}
The firm-level increments and the resulting coverage are printed in the paper's Table~A3, and the
group figure is \code{claims.json} key \code{cumulative.five\_A}.

\section{Reproduction and verification}
\code{verify.sh} performs, and exits non-zero if any stage fails:
\begin{enumerate}
\item \textbf{Integrity.} Every archived file is checked against \code{MANIFEST.sha256}; a modified
frozen input, script or manuscript fails here, before anything runs.
\item \textbf{Regeneration.} The analysis runs from \code{data/frozen/} only.
\item \textbf{Byte-identical re-run.} The regenerated \code{claims.json} and
\code{figures/Figure\_1.png} must be byte-for-byte identical to the committed ones; on a mismatch
the script prints the exact claim path and both values.
\item \textbf{Manuscript audit.} \code{build\_gate.py} reads every number out of \code{manuscript.tex}
and requires each to be reproducible from \code{claims.json}. The abstract's headline figures and
every row of both tables are additionally anchored to their source, so a number swapped for a
different valid one fails and is named. Exemptions --- years, structural cuts, figures inside quoted
10-K text, and series identifiers --- are listed explicitly in the source.
\item \textbf{Length.} The manuscript is checked against the journal's word limit.
\end{enumerate}
\textbf{Determinism.} The analysis has no stochastic component: no sampling, no bootstrap, no seed.
\code{claims.json} and \code{Figure\_1.png} are byte-identical across runs and across machines.
\code{Figure\_1.pdf} embeds a build timestamp and is therefore excluded from the byte comparison; its
pixel content is verified through the PNG.

\textbf{Environment.} Python~3.11.5 (standard library only for every reported number),
\code{matplotlib==3.8.0} (figure only), and, for the PDF only, \TeX~Live~2024 / pdf\TeX~1.40.26 with
\code{elsarticle}, \code{siunitx}, \code{tabularx}, \code{booktabs}, \code{microtype},
\code{seqsplit}, \code{caption} and \code{lmodern}. Exact versions in \code{environment.txt}.

\section{Data collection (not part of the reproduction)}
\code{code/collect\_*.py} document how the frozen inputs were originally collected:
\code{collect\_capex.py}, \code{collect\_composition.py}, \code{collect\_revenue.py} and
\code{collect\_alt\_tags.py} pull the XBRL \emph{frames} series; \code{collect\_sic.py} pulls
registrant classifications; \code{collect\_ai\_intensity.py} retrieves each firm's most recent 10-K
and scores it against a dictionary fixed before any financing result was computed. This phase
requires internet access and is intentionally excluded from the reproducible core: the
\emph{frames} interface returns the most recently filed value for each fact, so a later collection
would pick up subsequent restatements. No API key is required at any point, and none is
distributed. All reported results derive only from the frozen inputs.
